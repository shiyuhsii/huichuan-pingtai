B3260012 最终回传版 · 本机网站接收桥

入口：receiver_site.py
参数：--site-url http://127.0.0.1:5317
      --port COM13              （可省略，自动寻找唯一 CH340）
      --output <归档目录>       （可省略，使用当前 Windows 真实桌面/FPGA检测记录）
      --probe-seconds 30        （可选，限定测试时长；正式运行请省略）

接收桥为可选功能，请按仓库首页说明单独启动；不要重复启动多个接收器。
可与已安装的原版 R2 接收器共存：
1. 原版 R2 已运行时，本桥不抢串口，只观察完整的 detection.bmp 和 record.json，转换无损 PNG 后导入网站。
2. 原版 R2 退出后，本桥自动接管串口；仅寻找 CH340，不打开 FTDI 下载器或蓝牙 COM。
3. 多个 CH340 同时存在时，请通过 --port 明确选择。

必须使用 B3260012 回传固件；本地旧 B3260013 的 FPGAIMG1 协议与它不兼容。
先让 HDMI 显示 PC READY，再重新冻结出现至少一处候选划痕的画面。
保持冻结直到保存成功。此固件不会补发接收器就绪前已完成的检测，也不会回传零划痕结果。

此版本实际回传的是左右并排的 HDMI 检测截图，包含灰度视图、边缘视图、红框和屏幕文字。
它不是无框原图，固件也没有另外发送结构化框坐标。网站以“设备检测截图”记录。
桥接程序会从左半灰度视图中，提取精确红色像素组成的完整矩形，作为可点击的复核区域。
右半边缘视图的重复红框不重复计数。坐标以整张截图的尺寸归一，并标记 boxesSource=display-overlay。
这些区域来自屏幕红框，不是新一次 CNN 推理；不提供置信度。断开的、相交的或模糊不清的框不会猜测补齐。
原始检测截图保留不变；预升级的同步身份与记录保持原样，避免自动重传覆盖已有人工作业。
归档保留 detection.bmp、record.json，另外保存无损 detection.png 和桥接 manifest。
record.json 中的 received_at 是电脑接收时间，不是摄像头硬件时间戳。
deviceId 是本地接收器安装身份，不是板卡的硬件序列号。

串口采用 460800、8N1；每 0.5 秒发送 R2 就绪命令。
打开 COM 和发送就绪命令不等于双向连通：只有实际收到合法检测帧才有设备回传证据。
原版 R2 占串口时，网站状态只说明“原版接收器正在运行”，板端 READY 请查看 HDMI。
只有完整行、帧元数据和 CRC 校验通过且本机磁盘落盘成功后，才向板子发送保存成功确认。
HTTP 同步由独立线程执行，网站关闭或暂时不可用不会阻止本机保存确认。
网站恢复后自动重试；已删除的同帧记录不会自动复活，内容冲突会停止重试并记录日志。

仅连接本机 HTTP 工作台，使用现有本地登录流程；禁止外部目标和外部重定向，不经过环境 HTTP 代理。
不上传到云端，不调用 AI 服务。

诊断文件：
.runtime/receiver.log       运行日志（自动轮转）
.runtime/status.json        当前 PID、连接状态、字节数和进度
.runtime/sync_receipts.json 已同步、已删除或冲突的记录回执

离线测试：python -m unittest -v test_receiver_site test_display_boxes
测试采用伪串口，不打开真实 COM。
